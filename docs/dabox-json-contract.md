# JSON-контракт pg_profile для DABOX

## Назначение

Один JSON-пакет переносит один завершённый снапшот с локального PostgreSQL-хоста
в агрегирующую БД. Прямое подключение агрегатора к исходному кластеру и `dblink`
не используются.

Контракт рассчитан на push-модель: локальный планировщик снимает снапшот,
формирует JSON и передаёт его внутреннему сервису DABOX. DABOX вызывает импорт
на агрегаторе и возвращает подтверждение только после успешной транзакции.

## Формирование на источнике

Последний имеющийся снапшот:

```sql
SELECT export_sample_dabox('local');
```

Конкретный снапшот с текстами запросов:

```sql
SELECT export_sample_dabox('local', 42, false);
```

Конкретный снапшот с обфускацией текстов запросов:

```sql
SELECT export_sample_dabox('local', 42, true);
```

## Структура конверта

```json
{
  "contract": "pg_profile.dabox.snapshot",
  "contract_version": 1,
  "event_id": "7669812140604854310:42",
  "created_at": "2026-09-04T14:00:00.000000+00:00",
  "source": {
    "cluster_id": "7669812140604854310",
    "server_name": "local",
    "server_created": "2026-09-01T10:00:00.000000+00:00",
    "pg_profile_version": "4.15"
  },
  "sequence": {
    "sample_id": 42,
    "previous_sample_id": 41
  },
  "sample": {
    "sample_time": "2026-09-04T13:59:58+00:00"
  },
  "content": {
    "encoding": "pg_profile.export_data.rows",
    "table_count": 47,
    "row_count": 1520,
    "rows": [
      {
        "section_id": 0,
        "row_data": {
          "extension": "pg_profile",
          "version": "4.15",
          "tab_list_section": 1
        }
      }
    ]
  }
}
```

`cluster_id` — PostgreSQL `system_identifier`, устойчивый идентификатор
физического кластера. `event_id` однозначно строится как
`cluster_id + ':' + sample_id`.

`content.rows` сохраняет штатный формат `export_data()`: номер секции и JSON-строку
таблицы. Это позволяет использовать проверенный импорт pg_profile вместо отдельного
парсера для каждой таблицы статистики.

Из пакета исключаются:

- поле `servers.connstr`;
- все локальные рабочие таблицы `last_*`;
- журнал ранее принятых DABOX-пакетов.

Тексты SQL являются чувствительными данными. Если агрегатор не должен их получать,
источник обязан вызвать экспорт с `obfuscate_queries = true`.

## Приём на агрегаторе

DABOX передаёт всё JSON-значение параметром:

```sql
SELECT import_sample_dabox($1::jsonb);
```

Функция выполняет импорт атомарно и возвращает число реально добавленных строк.
Для первого принятого пакета конкретного кластера допускается любой `sample_id`,
чтобы подключать уже работающие инсталляции.

Повторная доставка того же `cluster_id + sample_id + event_id` безопасна и
возвращает `0`. Это является идемпотентным успешным результатом, а не ошибкой.

После первого пакета функция требует одновременно:

```text
incoming.sample_id = latest_imported.sample_id + 1
incoming.previous_sample_id = latest_imported.sample_id
```

При нарушении импорт отклоняется сообщением `DABOX sample gap`. DABOX должен
сохранить пакет в своём inbox/quarantine, отметить недостающий номер и повторить
доставку после получения пропущенного пакета.

Аварийное принятие возможно только явным административным вызовом:

```sql
SELECT import_sample_dabox($1::jsonb, NULL, true);
```

Такой пакет получает `gap_accepted = true` в `dabox_import_log`. Это не делает
разорванный интервал пригодным для отчёта: стандартный `get_report()` требует
непрерывный набор снапшотов.

## Сервер на агрегаторе

Если префикс не передан, импорт создаёт имя вида:

```text
dabox_<последние 8 цифр cluster_id>_local
```

Можно передать согласованный DABOX-префикс вторым параметром:

```sql
SELECT import_sample_dabox($1::jsonb, 'prod-db-17_');
```

Импортированный сервер создаётся отключённым (`enabled = false`), потому что
агрегатор не должен пытаться снимать с него локальные снапшоты.

## Журнал и ответы DABOX

Успешные приёмы регистрируются в `dabox_import_log`. Рекомендуемое соответствие
результатов API:

- новый пакет импортирован — `200 OK` или `201 Created`;
- повтор уже принятого пакета — `200 OK`, идемпотентный ACK;
- обнаружен пропуск — `409 Conflict`, пакет помещается в quarantine;
- неверный контракт или содержимое — `422 Unprocessable Entity`;
- временная ошибка БД — `503 Service Unavailable`, источник повторяет отправку.

В транспортном API рекомендуется включить TLS, а JSON передавать с gzip-сжатием.
Аутентификация и подпись сообщения относятся к контуру DABOX и не реализуются
SQL-функциями pg_profile.
